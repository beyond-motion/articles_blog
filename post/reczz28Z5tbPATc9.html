仅两小时，我就搭建了一个 AI 模特摄影棚

查看原文 原文链接
点评旧认知是 Vibe Coding 的瓶颈在提示词技巧或模型强弱，读完会发现瓶颈在“动手前的确定性”：需求是否被问成可验收的条目、界面是否有统一组件与设计规范、每条需求是否有可追踪的状态格。可迁移到任何 AI 协作交付场景：内容生产、数据分析、内部工具外包，都可先建三份文档加一张状态清单，用五层漏斗拷问，用只读审查员加实操复核。下一步可验证：给自己一个真实小需求，强制问满九轮、画完首屏三方案，再对比无流程时的返工次数与漏功能数；也可测试“新会话接续”是否真能靠三份文档无损耗接力。
正文整理

作者把自研的产品经理 harness 升级到 6.0，并用它从零做出 AI 模特出图工具「视镜」：上传服装图、选模特与风格，几分钟生成整组模特上身图，全程两小时多，作者只负责回答问题和拍板。harness 装在 Claude Code 里，由一个叫「废才」的产品经理角色主导，结构是一份主控文件、六个 skill（分别对应拷问、设计、计划、开发、复核、发布）、两个子 Agent（审查员只读代码，探路员上网查证并附出处）、一个提交前检查 key 与类型检查的 hook，以及需求文档、设计规范、开发计划三份模板。核心机制是用需求清单的六列状态驱动流程推进，不强制固定顺序，从而解决 Vibe Coding 常见的问题：漏功能、界面丑、越改越乱。
