Node2Shell 更名 HTTP2Shell，Brotli RCE 影响范围引争议

查看原文 原文链接
点评旧认知是“看漏洞名就知道我是否受影响”，读完后应改为“看依赖实现与调用路径”。HTTP2Shell 这个名字会让人以为只要不做 HTTP 压缩请求体就安全，但手动调用 Brotli 解码同样落入攻击面，这与 Log4Shell 命名带来的误判是同一类错误。可迁移到任何漏洞披露阅读：先确认受影响组件与版本，再确认自己的调用路径，最后才看攻击是否需要认证。下一步可验证：核对项目是否直接或间接依赖 Node.js 内置 Brotli、brotlicffi 等实现，是否处于 22.x、24.x、26.x 修复版本之前，并检查是否存在对不可信输入做 Brotli 解压的路径。
正文整理

Aikido 博客披露 CVE-2026-111497：Brotli 解码器存在越界写漏洞，可导致未经认证的远程代码执行，最初以 Node2Shell 之名公开，后改称 HTTP2Shell。Node.js 已为 22.x、24.x、26.x 发布修复版本。但受影响清单、版本范围与利用条件仍不清晰，链接还指向 Python 包，社区因此批评命名过宽、范围被夸大，并提醒手动 Brotli 解码同样可能触发，真实影响范围仍需以原始公告为准。
