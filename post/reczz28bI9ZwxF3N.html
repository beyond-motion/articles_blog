这个开源项目把整本书翻译做成了一条流水线

查看原文 原文链接
点评读完会改变一个旧认知：以为 AI 翻译的上限取决于模型语言能力，实际上瓶颈在于上下文管理、状态持久化和一致性约束这些工程层设计。可迁移的场景很广：长文档摘要、代码库级重构、多章节内容生成、批量数据清洗，凡是「超过一个上下文窗口 + 需要中断续跑 + 需要跨段一致」的任务，都可以套用这套四段式模板——归一化、切块、并行单职责执行、哈希校验合并。下一步可验证的是：把术语表换成风格指南或 API 约定，看这套管道能否用于跨文件的一致性问题；也可以实测并发度与质量的权衡曲线，以及 manifest 加哈希这套状态机制在失败重试上的实际收益。
正文整理

开源项目 translate-book 本质是给 Claude Code 写的一个 Skill，把「用 AI 翻整本书」拆成一条可验证的流水线：先把 PDF、DOCX、EPUB 统一转成 Markdown，按长度切成 chunk，再派多个 subagent 并行翻译（默认并发 8 个），每个只负责自己那一段；翻完用 manifest 加 SHA-256 哈希做完整性校验，因此中断后可续跑；最后合并导出 HTML、DOCX、EPUB、PDF。术语一致性靠全书共享一份术语表，并在每个子任务里附带目标语言与相邻 chunk 的少量上下文来实现。项目脱胎于 claude_translater 的 shell 脚本，现重构为 agent skill，需 Python 3、Pandoc 与 Calibre 的 ebook-convert，MIT 协议。
