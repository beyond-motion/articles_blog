Codex 实战：Every 团队如何将这款智能工作区融入日常工作

查看原文 原文链接
点评读前容易以为“用好 AI 工作区”等于找到一套标准最优配置或更复杂的提示词技巧；读后发现真正的变量是三层：上下文供给（长线程、文件系统、可移植记忆）、委派粒度（像对下属一样给目标而非步骤）、反馈闭环（让 Codex 审计自己的配置与错误）。可迁移到任何通用型 agent 工具的上手，以及团队内部推广 AI 时“收集具体工作流案例而非统一培训”的做法。下一步可验证：任选文中一个提示词（如 Katie 的上下文文件夹或 Austin 的结果导向）跑一遍，观察 Codex 是否主动采访、自建结构，再对照自己现有配置，找出缺失的记忆层与规则层。
正文整理

Every 团队分享了 Codex 智能工作区的五种实战用法：Natalia 把 Codex 当低摩擦版 Claude Code 和直属下属，用于 CRM 搭建与家人医疗事务管理；Dan 用长线程、应用内浏览器和路由线程编排信息流；Katie 构建本地上下文文件夹与点子农场；Austin 采用结果导向、轻量配置并让 Codex 自我审计；Kieran 用同步文件夹做可移植记忆。每人附可复制的启动提示词，核心主张是没有标准答案，从真实用法中挑选适合自己的风格。
