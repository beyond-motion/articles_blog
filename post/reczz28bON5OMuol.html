编码智能体的外部沙箱模式及三种实现

查看原文 原文链接
点评旧认知是「给代理加确认弹窗」或「把整个代理连同运行时塞进容器」；新认知是信任边界应画在代码执行这一层，代理可以留在外面，沙箱只要是一个可替换的后端即可。更关键的是：网络白名单与凭据替换这类策略设计，比选哪种虚拟化技术更决定实际风险大小。可迁移到 CI 里跑不可信脚本、插件/扩展系统、自动化数据分析管道、多模型对比评测。下一步可验证：接入其中一种实现跑真实任务，测逃逸面、启动与执行开销、允许列表对常见开发流程的摩擦度，以及凭据替换能否覆盖目标 API 的各种认证方式。
正文整理

Simon Willison 与 AI 研究实验室 Prime Radiant 提出「外部沙箱」模式：编码代理留在宿主机，只有它生成的代码被送进专用沙箱执行，以降低误操作与提示注入的破坏风险。同时发布三个实现：external-sandbox-v86（Node.js 经 v86 在 WebAssembly 里跑 Alpine Linux）、external-sandbox-container（Python 服务器 + Apple Containers）、external-sandbox-quicksand（微软 Quicksand，把 QEMU 与 Alpine 打进 Python 包）。三者提供相同的 localhost API，可让 Pi、Claude Code、Codex 调用，并附带 HTTP/HTTPS 允许列表代理与凭据替换机制。
