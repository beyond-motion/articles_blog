Obsidian+Claude Code：我是如何把虚拟产品内容生产变成全自动的

原文链接：https://mp.weixin.qq.com/s/R6VMgxQOwrFP8AdvTmgsmQ

用AI批量生产内容，做着做着质量开始下滑——失忆、降智、反复套同一个模板。很多人以为是提示词的问题，其实不是。

圈友简哥，视觉设计师，用Obsidian+Claude Code把这个问题彻底解决了。他把自己的小红书虚拟电商业务全部接进这套系统：写文案、做封面到发布，一句话启动整条流水线，一天稳定出20-30篇笔记，内容越产越好。

如果你在用AI做内容，这篇建议你看完。

Part 1：关于我：一位极其爱折腾的设计师

大家好，我是简哥。

我是一位视觉创意设计师，在一家普通的民营公司上班，主要负责电商、市场宣传方面的设计工作。

下班时就是我个人的主场，拿起小红书电商项目就是干，从6点做到12点，一天14-15个小时，天天如此！

励志要用 AI + 审美做一家一人公司。

加入生财这一年多，前前后后也做过其他几个项目，小红书实物电商、AI自媒体等，都没有取得实质性的结果。

后面看了大量的精华帖，禅定了好几天，最后选择了小红书虚拟电商赛道，慢慢的就做到了现在。

原本以为实物电商是跟自己最匹配的项目，因为之前有做淘宝、抖音电商的经验，所以一开始就选择了小红书实物电商。

但是高频次的外出拍照、不断的选品、不断的分类大量的手机照片live图，感觉每周都在做同样却不见正反馈的事情，而且发货、售后、退款一度搞的我店铺瘫痪，心力交瘁。

不是说不能做，是虚拟电商可能更加的省力、省事，后端不用这么操心，做好前端就行。

对于虚拟电商，我要做的就是静下心来潜心创作就行——不用发货、不用售后、不用外出、不用拍照、不用预约场地、不用每周整理700-800张的实拍图，我觉得非常省心了！

Part 2：项目实操成果

真实的数据，真实的我

说实话，虽然参加了6次航海，但目前还没取得什么亮眼的成果。没有让人眼前一亮的数据，真的说起来有些惭愧，但我觉得，真实比完美更重要，所以还是选择坦诚分享。

我手上一共4个账号，做的一拖三的模式，2部手机，做了3个月左右时间，累计发布567条笔记。

截至4月15日的数据：

第一个账号：累计发布 217 条笔记
第二个账号：累计发布 146 条笔记
第三个账号：累计发布 124 条笔记
第四个账号：累计发布 80 条笔记

Part 3：搭建 Obsidian + Claude Code：自动化内容生产工厂

01 遇到的瓶颈：产能不足

随着我手上的账号越来越多，从一个、两个、三个、四个增加到四个账号的时候，我就发现一个 Claude 账号不够用。因为很快它就限制了你的使用时间，这是 Claude 唯一的一个不足之处。

所以它不能满足我四个账号每天生产笔记的基本要求。按照我的这几个 SOP 跑下来，它一个账号最多只能生成五到六篇笔记。而且这五到六篇笔记你不能怎么修改，如果修改的话，只能生成两到三篇。所以效率这一块就比较打折扣。

所以我每次工作的时候，一个人同时操控三个 Claude 账号去生成笔记：

每个账号可以跑 5 到 6 篇
三个账号一下子就能跑十几篇
一天下来可以跑 20 到 30 篇

所以这个产量，相对来说我还是比较满意的。

02 更深层的问题：AI 会"变笨"

但当我渐渐地批量生产出更多笔记，从 30 篇、60 篇、90 篇增加到 100 篇、200 篇时，我就发现 Claude 有一个相对致命的缺陷。

这其实不仅是 Claude 的问题，也是目前行业的通病，即上下文窗口的容量限制。

Claude 的窗口比较小，很容易聊着聊着就满了，不像 Gemini 那样拥有上百万 Token 的大窗口。

这就导致了一个问题：

在同一个聊天窗口内，当生成到 20 到 30 篇笔记时，后续内容的质量就会出现"降智"。
AI 会出现"失忆"现象，开始机械地套用相同的模板，导致产出内容质量变差。
最要命的是，你必须手动去干预和调整，调完之后虽然能好一段，但再跑几十篇，它又会反复出现同样的问题。

03 理解 AI 的本质局限

它不是真的"遗忘"，是注意力被稀释了。

你可以把 AI 的记忆想象成一张桌子。桌子大小是固定的，你们聊的东西越来越多，桌子就越来越满。新的东西放上来，旧的东西就会被推到边角，甚至掉到桌子外面。

所以你第一轮说的那句"安全上限1630px"，到第二十轮的时候，AI 不是"不想记"，是那条信息已经被压到桌子边角了，它的注意力根本顾不到那里。

它不是在偷懒，是在走"最省力的路"。

AI 是靠大量数据训练出来的。它见过的东西越多，就越容易往"最常见的答案"上走。

左右对比图、阶梯图、折线图——这些概念图结构它见过几百万次，生成起来最"顺手"。你不强制约束它，它就会自动滑回这条熟悉的轨道。

这不叫偷懒，叫模式坍缩——就像一个人走路，总会不自觉走最熟的那条路，哪怕那条路你已经走过一百遍了。

04 为什么提示词再完美也解决不了

这跟提示词的完美和 Skills 专业严密没有关系。

提示词写得再完美、Skills 再严密，都解决不了底层的结构问题。

原因很简单——提示词和 Skills 本质上是注入到上下文里的文字。它们占的是桌子上的空间，不是给 AI 装了一个新的 CPU。

桌子还是那张桌子，大小还是那么大。

05 找到解决方案：Obsidian + Claude Code

怎么样解决这个问题呢？我又不能不用 AI，一用 AI 时间久了，我批量生成的时候又会出现这个问题。

后面我不但翻阅了小红书，翻阅了深藏的很多帖子，直到这次的 AI 航海大会，我才真正找到了解决办法：借鉴焦波老师的"夜话"，用 Obsidian 搭建知识库这个点，我深入去挖掘了关于 Obsidian + Claude Code 这套方法，后面慢慢了解到，它确实可以用来沉淀、制作并生产很多的笔记。

我现在一句话就能启动整条流水线。

核心是我在电脑里搭了一套系统，把我15年做设计积累的所有东西——选题方法、关键词库、封面规范、写作套路——全部存进去了。

AI 每次打开就自动加载这些内容，不用我反复解释背景。

06 从0到1：完整生成一套笔记

第一步：选一个选题
打开 Claude Code，直接说：「规划第X轮选题」
AI 会自动读取选题库，按照固定配比（3篇品牌拆解 + 7篇精准转化）给你筛出10个选题。

第二步：写文案
确认完选题后，直接说：「写第X篇笔记，选题是：[选题名称]」
AI 会输出一套完整的东西：P1 封面文案、P2-P5 内容页文案、P6 总结页文案、小红书正文（700-800字）、话题标签（10个）、评论区文案。

第三步：去 Gemini 生成人设图
在 Claude Code 外面做，AI 没法帮你生成真实照片。

第四步：做封面（P1-P6）
人设图放好之后，回到 Claude Code，说：「做第N篇笔记的封面」
AI 会依次生成 6 个 HTML 文件。

第五步：截图出图
HTML 做完之后，AI 会自动运行截图脚本（用 Playwright），把6个 HTML/SVG 文件批量截成 PNG。

第六步：优化思路：进化学习系统
每做完几篇笔记，发出去跑一段时间之后，你会知道哪些写法效果好、哪些没用。
这时候可以做进化学习：说「执行进化学习」，AI 会自动对比原稿和你改过的终稿，提取你的修改规律，写进进化系统/修改规律.md。
下次再写新笔记时，AI 会先读这个文件，把你之前验证过有效的写法直接内化进去，越写越准。

07 为什么 Obsidian + Claude Code 能解决问题

因为这套系统不再依赖于 AI 的记忆，而是依赖于 Skill 的强制化的规则去运行。规则不会改变，但是记忆可能会越来越被稀释。

规范永远在，不会被稀释
行宽安全上限1630px、概念图安全区坐标、字体路径——这些写成 .md 文件存在项目里。每次生成前 Claude Code 主动读取，不依赖上下文里还剩多少空间。

自检可以变成真正的自动化
Claude Code 可以写成：生成一行正文 → 立刻跑验证 → 超出就直接重写，不进入下一步。
这个闭环不依赖 AI 的注意力，是程序级别的强制执行，不会"忘"。

历史修正记录可以真正保存
你之前纠正过我的每一条——P7金句没居中、概念图文字叠加、字体未声明——这些都可以记录在我的进化日志 Skill 里，每次启动前自动读入，相当于给 AI 一份"踩坑备忘录"。

08 时间被释放了

所以搭建完这套系统，我感觉自己的时间也被释放了。

以前是坐在这边，我动 AI 才动，我不动 AI 就不动；而我现在下完指令之后，可以出去游荡一会儿再回来，AI 还在帮我制作东西，基本处于一个半自动化的状态。

如果出了错，它会自己打回、自己修正，不断地自我进化。

这套系统越用越活，会根据你自己的特点写出匹配你风格的文章，越用越像你。

Part 4：给正在同行者的一点点建议

01 数据稳定的时候，尽量不要去修改详情页
我之前踩过的一个坑，就是因为觉得详情页主图不够漂亮，我自己又设计了一套，然后大篇幅地去调整修改了，导致这个产品流量直线下降，花了很长时间才养回来。

02 如果客户申请仅退款，你就给他退吧
因为你如果不退，他可能后面会投诉，一旦投诉，基本上很难申诉成功。
这时候你的店铺里就会多了一条"平台介入率"。这个平台介入率是考核你 90 天之内的投诉数量除以店铺的下单数量，非常影响搜索渠道的流量和搜索权重。
