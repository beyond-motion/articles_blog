为什么你应该烧掉更多 Token

查看原文 原文链接
点评读完会改变一个旧认知：把 token 账单低当作「节俭美德」或效率证明，其实可能只是野心的天花板太低。新的框架是把 AI 支出看作研发投入，用损益表而非预算表管理：先找瓶颈，再让 AI 去消除，最后才做成本收益分析。可迁移场景包括团队算力治理、个人 API 开销管理、以及任何「投入可计量但产出不确定」的探索型工作。下一步可验证：挑一个近期异常耗 token 的任务，用文中提供的审计 prompt 回溯会话记录，拆解必要工作与协调浪费，再针对指令、模型选择、agent 层级各做一处改动，对比同等效果下的成本变化。
正文整理

Every 的 CEO Dan Shipper 的 token 消耗量是公司第二高用户的三倍多，这个差距让他反问：其他人是不是因为想得太小而压低了 AI 账单？他主张不设统一token预算，而是用「这次花了多少钱、换来了什么、学到了什么」三问来评估每次昂贵运行。文中以视频负责人 Randy 烧掉 45 亿 token 做 3D 模型的失败实验为例，说明失败实验如何暴露出 agent 编排架构的浪费，并沉淀出可复用的基准和更精简的设置；同时给出审计 token 消耗的 prompt，以及 Marcus 按任务难度分配 Fable、Opus、Sonnet 的工作流。
