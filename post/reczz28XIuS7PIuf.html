打造更高效的 Agent：Every 团队如何将 Token 成本降低 80% 以上

查看原文 原文链接
点评旧认知是「省钱要靠路由、分层、更便宜的模型」；新材料表明，巧妙的架构反而可能翻倍计费，而缓存命中、工具返回体积这类「无聊细节」才是量级差异所在。可迁移到任何按量计费的 AI 系统、API 网关、RAG 管线：先建立成本可观测性，再做优化。另一个增量是把 AI 当「调查伙伴」而非「代码生成器」——先解释系统、再提假设、再实测、最后追根因，且始终区分实测与估算、先不部署。下一步可验证：检查自己系统的系统提示词是否逐请求变化导致缓存失效，以及工具返回是否携带了模型用不到的字段。
正文整理

Every 团队发布 Slack 内的公司级 Agent，因 Token 成本不加价转嫁用户，效率成为产品的一部分。工程师 Paridhi Agarwal 放弃「便宜模型先分流」的复杂方案（实测成本反升），转而排查系统浪费：升级 Opus 5.5、精简工具返回内容与按需加载、并修复因记忆文件夹名含 Slack ID 导致缓存无法跨用户复用的 Bug，11 个高频任务 Token 成本降超 80%。文章还给出四步工作流：说明目标并给上下文、设计修复方案、测量验证、追查遗留问题。
