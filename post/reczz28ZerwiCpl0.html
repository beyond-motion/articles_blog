这应该是我写过最全的 Opus 5.5 提示词工程讲解了

查看原文 原文链接
点评读完后会被迫放弃两类旧习惯：一是靠“请务必认真、全面、你是资深工程师”加长提示词，二是靠“再检查一遍”“继续”推动进度。新的认知是：提示词的质量等于可验证性——现象能否复现、结论能否回到文件或原文、测试究竟跑没跑。可迁移到给同事布置任务、写需求文档、验收外包、做项目复盘：先定义问题与边界，再谈方案。下一步可验证：挑一个熟悉的 bug 修复任务，固定提示词只改 effort 档位，比较的不是回复长度，而是返工次数与漏检项。
正文整理

文章依据 Anthropic 官方 Opus 5.5 提示指南整理，面向已在使用该模型但还不熟悉提示词与思考设置的用户。内容覆盖：如何把问题现象、触发条件、完成标准和检查要求写清楚；如何提供文件、报错与版本信息作为上下文；effort 五档（low/medium/high/xhigh/max）如何选择与切换；如何让模型交出可核对的检查结果和进度，而不是只说“已完成”；读外部文档时如何区分资料与指令以防间接提示注入；以及子 Agent 分工、提示词迭代收敛，末尾附 API 参数细节。
