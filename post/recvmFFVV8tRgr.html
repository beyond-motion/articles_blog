部署 HTML 页面从未如此简单！

之前有一个很无聊的讨论：到底应该用 Markdown，还是用 HTML？

这个问题其实有点像在问到底是榴莲好吃，还是水果好吃？

因为Markdown 的本质就是从属于HTML的标记语言。

Markdown从设计之初就是为了忽略样式，为的是让人更快地书写内容，摆脱复杂的标签样式排版，把注意力放回文字本身。之前还写过专门的一个 Markdown 本地桌面端工具Grok Builder太香了！做了一个更趁手的Markdown工具。

再后面又有了 MDX 这种东西，可以直接在 Markdown 里混合写HTML组件，甚至是交互逻辑。

所以讨论谁取代谁没有任务意义，重点是场景。

在AI 时代，Markdown 早已经是最通用的语言了。因为它足够简单，结构又足够清晰，最适合于提示词、文档、教程、知识库、训练样本、AI 编程的上下文。

HTML 则更适合做最终展示，尤其是那些需要更强视觉表现、更复杂布局、更丰富交互的页面，比如在Vibe Coding展示各种架构图，组件和更直观的状态流转。

像是SVG、图表、图片、卡片、按钮、二维码、富文本排版等等。

HTML最方便还是它的分享属性。

跨平台，多端可用，比如我说就用它来做分享群的二维码。

https://art.bytenote.net/qrcode

之前我处理这类 HTML静态页面，走的是一套很传统的 CI/CD 流程。

本地改完文件之后，先 commit，再 push 到 GitHub。GitHub 收到代码之后，Cloudflare 再去拉取仓库，然后重新构建、部署，最后生成线上页面。

这套流程当然没问题，但是，链路太长了。

从本地提交，到 GitHub，再到 Cloudflare，中间任何一个环节出问题，都可能导致部署失败，为了确认它有没有部署成功，还得去看构建日志、看状态、看访问结果。要是再认真一点，还要配一套监控。

对于一个正式项目来说，这样做没问题。对于一个简单的二维码分享页来说，就显得有点太重了。

比如第一个群满了，我只是想换一张二维码图片，再生成一个新的分享页面。结果还要重新走一遍提交、推送、构建、部署。

后来我就想，有没有一种更简单的方式？

最好是我把写好的 HTML 直接拖进去，它就自动上传、自动生成一个可以访问的链接。

不需要本地 Git，不需要 GitHub，不需要复杂的 CI/CD，也不需要每次都去看构建日志。

于是我就写了这个非常轻量的部署工具，视频演示如下：

它的操作很简单，我在后台页面里直接拖入一个 HTML 文件，系统接收之后，把它保存，然后通过 Cloudflare Worker 对外提供访问。

这样一来，每次我要更新二维码页，就只需要重新生成一个 HTML 文件，然后拖进去。

第二个群满了，我换一张二维码，再拖一次，页面就更新了，链接也可以继续分享。

整个过程不需要服务器，不需要数据库，不需要传统构建流程，也几乎没有额外成本。

因为整套东西都跑在 Cloudflare 上，之前我在AI前端小课从零到全栈的开箱即用！Cloudflare 全家桶SaaS Template架手架就已经对它做了详细的介绍。

Cloudflare 提供了大量慷慨的使用额度，本身就提供了比较完整的生态，包括 Worker、路由和访问控制，本次源码的部署也可以在 Cloudflare上部署，完全 03 费用。
