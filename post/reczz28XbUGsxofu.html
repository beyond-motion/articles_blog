PHP 8.2.35 标签发布，社区讨论指向严重 RCE

查看原文 原文链接
点评旧认知是“看到版本发布就默认漏洞已修”；新认知是版本标签、CVE 编号、官方公告是三种不同证据，混用会高估确定性。可迁移到任何依赖社区情报的技术决策场景：应急响应、供应链风险评估、内部安全通告撰写。下一步可验证三件事：官方 changelog 或安全公告是否确认这两个 CVE；8.5.12 与 8.4.27 的实际补丁状态；发行版打包是否已同步修复。同时应把“未认证 HTTP 请求即可在 worker 内复用已释放内存”作为排查假设，而非常识引用。
正文整理

PHP 8.2.35 的发布标签出现在 php-src 仓库，但条目未附变更日志或安全公告，无法自行核实修复内容。Hacker News 讨论将该版本与据称的严重 PHP 远程代码执行漏洞及协调披露联系起来，提及 Wiz、Calif、OpenAI、php2shell 及两个 CVE 编号，并称 8.5.12 仍受影响、8.4.27 缺 amd64 镜像。这些说法均来自评论，受影响范围与实际风险仍待官方通告确认。
