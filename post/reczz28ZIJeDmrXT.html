医疗保健公司 Headway：自建了一款买不到的 AI 工具

查看原文 原文链接
点评读完后被修正的旧认知是：自建还是采购，不是能力高低的比较，而是对"维护责任"的定价——自建并不省钱，它等于买下一款买不到的产品，同时接手供应商原本承担的工作（可靠性、延迟、跟进外部创新、需求排队）。可迁移之处：任何要在敏感数据上放开 agent 自主权的场景，都可用"沙箱化＋最小连接＋外发拦截"把审批成本转成架构成本；内部工具的推广靠产物质量和连接器覆盖，而非自上而下的强制。下一步可验证：先让靠近前沿的三四名工程师用一个季度探索而非固定路线图，法务、合规、安全早期入场划定访问边界，工程试点跑通后再扩面；同时为每项外部新功能设定"直接使用还是复刻进内部"的定期复盘机制。
正文整理

心理健康医疗公司 Headway 在通用 AI 产品无法同时满足其安全、合规与工作流约束的情况下，基于 Claude Code SDK 在自有 AWS 环境自建内部 AI 助手 Eddy：每段对话运行在一次性的 Docker 容器中，数据只读、外发受限，因此 agent 可以自主行动而不必逐步请求批准。900 名员工中 650 人每天使用，累计约 26 万次对话。代价是自行承担可用性、启动延迟、功能迭代与安全维护，作者据此给出"等待—购买—自建"的判断框架。
