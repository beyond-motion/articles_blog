Who Isn't Using GPT 5.5

查看原文 原文链接
点评读完需要修正两个旧认知：一是“更好的模型会自然赢得用户”，实际发生的是工作流锁定，所以评估新工具应核算迁移成本，而不是只看基准分数；二是“AI 提效等于写得更快”，真实跃迁来自把整条链路自动化，人类从执行者变成审核者。可迁移到任何工具选型与个人工作流改造：先问自己能否把重复的观察和实现交给代理，再问自己是否因为沉没成本在坚持低效方案。此外，“永远只差一个提示词”的赌博感是真问题，下一步可以验证：给自己设定“满意即停”的止损规则与时间盒，并观察在 Codex 与 Claude Code 之间做双轨分配时，哪些任务实际获得增益。
正文整理

文章围绕 GPT-5.5 发布一周后的实际使用情况展开：Every 团队多数成员认可它的速度与执行指令的能力，但因为已经深度绑定了 Claude 特有的代理工作流，迁移成本成了主要障碍。另一条线索是，多位估值超十亿美元公司的前 CTO 转投 Anthropic 做个人贡献者，回到写代码的一线。作者还记录了 Kieran 通过让代理观看用户录屏、夜间自动提交 PR，一天合并 24 个 PR 的案例，并反思编码正变得像老虎机式的成瘾体验。
