我们为何把 Agent 的基础设施交给 Anthropic

查看原文 原文链接
点评旧认知是“自建 agent 等于更强控制、更低成本”；读完后会发现，隐性运维与“宠物化”会先耗尽工程团队的时间，而基础设施本身正在变成商品。新的抓手是：护城河在“同事感”——判断一条消息是否冲自己来、代表谁行动、记忆跨会话累积、技能改动需所有者批准。可迁移到任何自建与托管的取舍：先估算照看成本，再估算迁离成本（那份替换清单往往比预想的长）。可验证的动作包括：为长会话设置 session 轮换与简短回顾、监控缓存命中与单轮成本、在模型升级后回归测试回复长度与格式。
正文整理

Every 团队为了让每位员工都有一个 agent 来提升产出，先用 OpenClaw 搭建了 Plus One，结果不得不全天候维护几十台云机器、处理登录过期与记忆重叠，agent 于是变成了高维护的“宠物”。他们随后转向一个全公司共享、住在 Slack 里的 @Every，并把它搭建在 Anthropic 的 Claude Managed Agents 之上，由后者负责 harness、session、缓存、压缩与沙箱，团队只专注于“像同事”的界面层：判断消息是否冲自己来、代表谁行动、权限与技能审批。文章也坦承被绑定在 Claude 模型与 CMA 设计上、无法满足零数据保留等取舍。
