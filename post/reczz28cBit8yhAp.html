Anthropic 如何让 Claude 变得更可靠？

查看原文 原文链接
点评读完会改变一种旧认知：以为提示词工程和自建协调架构是核心竞争力，实际上它们可能只是平台能力缺位时的临时替代方案。可迁移的场景包括代码迁移、大文件转换、需要多方交叉审核的批量任务，以及任何“人肉当审核子智能体”的重复劳动。更值得带走的是两条可验证路径：一是在复杂项目里显式用 workflow 或 ultracode 让 Claude 生成脚本化编排，观察它是否比逐轮纠错更稳定；二是对重复任务先问智能体“要稳定每周运行还需我提供什么”，用它的追问反推规则、示例和好坏标准。同时也要接受前沿追逐的选择性放弃——把注意力留给头部模型与真正好用的工作流。
正文整理

文章以 Claude Code 的动态工作流功能为主线：过去工程师要靠协调智能体、子智能体和本地 Markdown 文件手动绕开上下文窗口限制，而动态工作流让 Claude 直接写出可复用脚本，按需生成指定数量的子智能体并互相校验，大幅提升复杂多智能体任务的可靠性。文中还附了设计稿转代码的案例、Every 团队“允许自己略过”哪些 AI 动态的快问快答，以及把 Slack 机器人当新同事培养的三步工作流。
